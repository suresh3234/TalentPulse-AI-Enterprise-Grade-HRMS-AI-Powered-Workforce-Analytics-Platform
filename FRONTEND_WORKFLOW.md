# 🖥️ AI HRMS - FRONTEND WORKFLOW & DEMO GUIDE

This document provides a comprehensive overview of the frontend user flows, API integrations, and the demonstration path for the AI-Powered HRMS Platform.

## 1. ARCHITECTURE OVERVIEW

The frontend is built using **React + Vite** and uses standard CSS modules for styling. 
- **Routing**: Client-side routing managed by `react-router-dom`.
- **State Management**: React Context API combined with standard React hooks (`useState`, `useEffect`).
- **API Communication**: The `frontend/src/api/api.js` file handles all outbound Axios requests, injecting the JWT bearer token into the `Authorization` header.

## 2. USER DEMO FLOW

When demonstrating the platform, follow this sequential flow to showcase all capabilities:

### Step 1: Authentication
- Navigate to the **Login Page**.
- Enter credentials (HR Admin or Manager).
- The system validates the token and redirects to the Main Dashboard.

### Step 2: Main Dashboard
- **Overview**: The dashboard aggregates high-level metrics (Total Employees, Active Leaves, Recent Anomalies).
- **AI Integration**: Point out the "AI Insights Summary" widget, which pulls data from `GET /api/ai/employee-summary/all`.

### Step 3: Employee Management
- Navigate to **Employees**.
- **View List**: Shows the standard employee roster.
- **Detailed Profile**: Clicking on an employee routes to their profile page.
- **AI Analytics**: Within the profile, click on the **AI Analysis** tab.
  - This calls `GET /api/ai/full-analysis/:employeeId`.
  - It displays Activity Insights, Attendance Predictions, and prioritized Recommendations generated by the Groq AI engine.

### Step 4: Recruitment Workflow
- Navigate to **Recruitment**.
- Show the Kanban-style candidate pipeline (Applied -> Interviewing -> Offered).
- **AI Screening**: Highlight how the system automatically screens uploaded CVs and flags top candidates based on skill match.

### Step 5: Notifications & Reports
- Demonstrate the real-time notification drop-down (notifying HR of critical anomalies, such as consecutive absences).
- Navigate to **Reports**, showing exportable charts of attendance and performance metrics.

## 3. KEY API INTEGRATIONS

The frontend interacts with the following critical endpoints:

| Feature | Endpoint | Method |
| :--- | :--- | :--- |
| **Authentication** | `/api/auth/login` | POST |
| **Employee List** | `/api/employees` | GET |
| **AI Full Analysis** | `/api/ai/full-analysis/:id` | GET |
| **AI Predictions** | `/api/ai/predict-attendance/:id`| GET |
| **Recruitment** | `/api/recruitment/candidates` | GET |

*Note: All endpoints are prefixed with the base URL defined in the `.env` file under `VITE_API_URL`.*

## 4. UI/UX CONSIDERATIONS

During the final cleanup phase (FE1), the following standards were enforced:
- **Responsive Design**: All tables and charts gracefully collapse on mobile viewports.
- **Error States**: Graceful error handling UI if an API request fails (e.g., "Unable to load AI Insights").
- **Loading States**: Skeleton loaders and spinners active during heavy AI operations (which can take ~2 seconds).
- **Clean Console**: Removed all unused variables, deprecated React features, and `console.log` statements for a clean production build.
